## 📦 Service Request & Response Payload Format (May 2026)

The GenAI LOC Tracker now uses a modern, extensible JSON structure for all service requests and responses. This change improves clarity, future-proofs integrations, and makes it easier to add new fields.

### Request Payload Example
```json
{
  "meta": {
    "developerId": "dev-001",
    "developerName": "Alice",
    "projectId": "MyProject",
    "sprintId": "Sprint-42",
    "ideType": "IntelliJ",
    "genAiTool": "Copilot",
    "developmentMode": "AI_ASSISTED",
    "llmModel": "gpt-4o",
    "agentName": "GitHub Copilot",
    "sessionId": "session-xyz",
    "eventTimestamp": "2026-05-10T12:34:56Z"
  },
  "summary": {
    "linesAdded": 35,
    "linesModified": 6,
    "linesDeleted": 2,
    "genAiGenerated": true,
    "genAiConfidenceScore": 0.98
  },
  "files": [
    {
      "filePath": "src/com/example/Foo.java",
      "fileName": "Foo.java",
      "className": "Foo",
      "linesAdded": 25,
      "linesModified": 4,
      "linesDeleted": 2
    },
    {
      "filePath": "src/com/example/Bar.java",
      "fileName": "Bar.java",
      "className": "Bar",
      "linesAdded": 10,
      "linesModified": 2,
      "linesDeleted": 0
    }
  ],
  "acceptedLocation": "CODE_EDITOR"
}
```

### Response Payload Example
```json
{
  "eventId": "abc123",
  "meta": { ... },
  "summary": { ... },
  "files": [ ... ],
  "totals": {
    "filesUpdated": 2,
    "filesAdded": 1,
    "filesDeleted": 0
  },
  "acceptedLocation": "CODE_EDITOR",
  "createdAt": "2026-05-10T12:34:57Z",
  "updatedAt": "2026-05-10T12:34:57Z"
}
```

#### Field Descriptions
- **meta**: Developer, project, session, and tool metadata.
- **summary**: Aggregated LOC and confidence for the event.
- **files**: Array of per-file LOC changes (path, name, class, lines added/modified/deleted).
- **acceptedLocation**: Where the AI-generated changes were accepted (e.g., CODE_EDITOR, COPILOT_CHAT).
- **totals** (response only): Backend-calculated file totals for the event.
- **createdAt / updatedAt**: Timestamps for event persistence.

> **Note:** All previous flat fields (developerId, linesAdded, fileChanges, etc.) are now nested for clarity and extensibility.

## 1. Solution Overview

**GenAI LOC Tracker** is a two-component system that measures how much code in a software project is generated by AI coding assistants (GitHub Copilot, Claude, ChatGPT, Gemini, etc.) versus typed manually by developers.

| Component | Technology | Role |
|---|---|---|
| **intellij-plugin-claude-ij** | Java / Kotlin, IntelliJ Platform SDK, Gradle | IntelliJ IDEA plugin — detects and captures LOC events |
| **intellij-plugin-loc-service** | Java 21, Spring Boot 3.3, MongoDB | Backend REST service — stores and queries LOC events |

### 2.3 Data Flow

```
 Developer codes in IntelliJ IDEA
          │
          ▼
 GenAiDocumentListener fires on every document change
          │
          ├─► Counts: linesAdded / linesModified / linesDeleted
          ├─► Classifies: genAiGenerated = (linesAdded >= threshold)
          ├─► Resolves: developerId, developerName (Windows login / Git)
          ├─► Detects: genAiTool (from installed plugins)
          └─► Builds: CodeEventRequest
                    │
                    ▼
          EventDispatcher — buffers events in memory queue
                    │
          ┌─────────┴──────────────────────────────┐
          │  Every flush.interval.seconds            │
          │  OR when queue >= batch.size             │
          └─────────┬──────────────────────────────┘
                    │
          ┌─────────▼──────────────────┐   Backend UP?
          │  POST /api/v1/genai-loc/   │──── YES ──► HTTP 201 Created
          │  events  (or /batch)       │              └► Replay CSV if exists
          └────────────────────────────┘
                    │
                  NO (backend unreachable)
                    │
                    ▼
          CsvFallbackStore
          ~/.genai-loc/fallback-YYYYMMDD.csv
```

### Step 5 — Configure the Plugin

After restarting IntelliJ IDEA, configure the plugin via the Settings UI:

1. Go to **File → Settings → Tools → GenAI LOC Tracker**

| Field | Description | Default |
|---|---|---|
| **Backend URL** | REST endpoint to post events | `http://localhost:8080/api/v1/genai-loc/events` |
| **Developer ID** | Your employee/user ID | Auto-detected from Windows login |
| **Developer Name** | Your display name | Auto-detected from Git config |
| **Project ID** | Project identifier | Auto-filled from IntelliJ project name |
| **Sprint ID** | Current sprint ID | Blank (fill manually) |
| **GenAI Tool** | Override the auto-detected tool | Auto-detected from installed plugins |
| **Plugin Enabled** | Toggle tracking on/off | `true` |
| **Batch Size** | Events buffered before flush | `10` |
| **Flush Interval (sec)** | Background flush frequency | `30` |
| **GenAI Line Threshold** | Min lines to classify as AI-generated | `3` |

2. Click **Apply** → **OK**

> Alternatively, edit `genai-loc.properties` at the project root directly.

## 6. Configuration Reference

### Plugin — `genai-loc.properties`

```properties
# REST API endpoint (must match backend service URL)
backend.url=http://localhost:8080/api/v1/genai-loc/events

# Developer identity (blank = auto-detect from Windows login or Git)
developer.id=
developer.name=

# Project and Sprint metadata
project.id=
sprint.id=

# GenAI tool override (blank = auto-detect)
# Values: COPILOT | CLAUDE | CHATGPT | GEMINI | CODEWHISPERER | TABNINE | CODEIUM | OTHER
default.genai.tool=

# Enable/disable the plugin
plugin.enabled=true

# Buffering: flush after this many events
batch.size=10

# Buffering: flush every N seconds (background thread)
flush.interval.seconds=30

# Minimum inserted lines to flag as GenAI-generated
genai.line.threshold=3
```

> Runtime changes via Settings UI are saved to:
> `~/.config/JetBrains/<product>/options/genai-loc.xml`

## 7. REST API Reference

**Base URL:** `http://localhost:8080/api/v1/genai-loc`

### Event Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/events` | Submit a single LOC event |
| `POST` | `/events/batch` | Submit multiple LOC events |
| `GET` | `/events` | List all events (paginated) |
| `GET` | `/events/{id}` | Get event by MongoDB ID |
| `PUT` | `/events/{id}` | Update an event |
| `DELETE` | `/events/{id}` | Delete an event by ID |
| `GET` | `/events/developer/{developerId}` | Events by developer (supports `?from=&to=`) |
| `GET` | `/events/project/{projectId}` | Events by project (supports `?from=&to=`) |
| `GET` | `/events/developer/{devId}/project/{projId}` | Events by developer + project |
| `GET` | `/events/tool/{genAiTool}` | Events by AI tool |
| `GET` | `/events/session/{sessionId}` | Events by session |
| `GET` | `/events/project/{projectId}/sprint/{sprintId}` | Events by sprint |
| `DELETE` | `/events/session/{sessionId}` | Delete all events in a session |

### Summary Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/summary/developer/{developerId}?from=&to=` | Aggregated stats for a developer |
| `GET` | `/summary/project/{projectId}?from=&to=` | Aggregated stats for a project |
| `GET` | `/summary/project/{projectId}/sprint/{sprintId}` | Aggregated stats for a sprint |

## 8. Offline / CSV Fallback

When the backend service is **unreachable**, the plugin automatically saves events to a local CSV file:

```
~/.genai-loc/fallback-YYYYMMDD.csv
```

### CSV Columns

```
developerId, developerName, projectId, sprintId, filePath, fileName,
ideType, genAiTool, developmentMode,
linesAdded, linesModified, linesDeleted,
genAiGenerated, genAiConfidenceScore, eventTimestamp, sessionId
```

### Auto-Recovery Flow

```
Backend UNREACHABLE                    Backend RECOVERS
─────────────────────────────────      ──────────────────────────────
Plugin flush() fails                   Plugin flush() succeeds (HTTP 2xx)
  └─► Events written to CSV              └─► replayFallback() triggered
                                               └─► All CSV rows POSTed
                                               └─► CSV file deleted ✅
```

> If replay also fails, the CSV is **retained** and automatically retried on the next successful flush.

## 10. Troubleshooting

| Problem | Cause | Solution |
|---|---|---|
| Plugin not tracking events | `plugin.enabled=false` | Enable in Settings → Tools → GenAI LOC Tracker |
| Events not reaching backend | Wrong `backend.url` | Verify URL in settings; check backend is running on port 8080 |
| Backend returns 500 | MongoDB not running | Start MongoDB: `net start MongoDB` |
| CSV fallback not replaying | Backend still down during flush | Wait for backend to recover; replay triggers automatically |
| GenAI tool shows `OTHER` | No supported AI plugin installed | Manually set `default.genai.tool` in settings |
| Build fails — SSL error | Zscaler proxy / corporate firewall | Run `import-zscaler-cert.bat` in the plugin project root |
| `gradlew.bat runIde` is slow | First-time IntelliJ SDK download | Normal; subsequent runs are fast (cached in `~/.gradle`) |
| Swagger UI not loading | Service not started | Start the backend service on port 8080 first |
| MongoDB connection refused | MongoDB not installed | Install from https://www.mongodb.com/try/download/community |
